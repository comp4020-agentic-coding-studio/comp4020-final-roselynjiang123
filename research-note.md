# Does Fresh Context Make an Independent Reviewer?

Anthropic's Claude Code guidance calls a second session “the easiest independent reviewer you can get”, since it has not seen the reasoning behind the code (Anthropic, n.d.). Cognition reports that its Devin Review works best when it shares no context with the coding agent, finds about two bugs per Devin-written pull request, roughly 58% of them severe, and inherits only the bias of a training process assumed to be “quite high-quality” (Yan, 2026). Yet finding additional bugs and avoiding shared failures are different achievements. I distinguish procedural independence, which limits influence between reviewers, from statistical independence, which concerns whether their failures are related. I argue that a fresh reviewer should lose the author's reasoning and rebuttals, keep its own unresolved findings and accept a change only on evidence that does not rest on the author's account; even then, its contribution has to be measured rather than assumed.

For medication double-checks, the Institute for Safe Medication Practices Canada (ISMP Canada, 2005) suggests reading pump settings before consulting the order, so the second practitioner observes without being told the expected reading. Westbrook et al. (2021) observed 3,296 primed checks, where one nurse shared potentially influential information, among 3,563 administrations requiring double-checking; only 36 checks were independent. The hospital's policy explicitly required independence. Although these observations cannot settle whether independent checking reduces errors, they suggest that labelling a process independent does little without controlling information flow. My medication-checking game enforces this by hiding each player's answer until both have submitted.

An explanation can change a verdict while the defect survives. Alexopoulos et al. (2026) found that Claude Code accepted one of 17 vulnerable changes with a one-line description. LLM-generated attack metadata raised this to eight, and feedback-driven refinement achieved acceptance in all 17 within four rounds. In the Claude Code runs, attacker and reviewer used the same LLM. Template framing, by contrast, was largely ineffective against both Claude Code and CodeRabbit. Removing descriptions, commit messages and comments recovered misses attributable to framing. In one CodeRabbit case, a search matched a planted comment, prompting acceptance although the executable code was unchanged. Comments are therefore part of the problem, not information safely outside the diff. Because benign descriptions were not tested, ordinary author explanations still need separate evaluation.

The authors highlight the asymmetry behind this result: the attacker learns from every rejection, while the reviewer judges a single polished pull request with no view of earlier attempts (Alexopoulos et al., 2026). A review loop that discards earlier findings could reproduce it without malice: the coding agent keeps feedback that each fresh reviewer never sees. Cognition reports repeated review cycles without saying whether findings carry over (Yan, 2026). I propose preserving a compact record of unresolved findings while initially withholding the author's rebuttals. The reviewer would recheck each defect, then weigh the explanation and record any dismissal. Inherited findings might anchor later reviewers, so they should be retested as open questions, leaving room for new ones. Fresh context should limit persuasion while preserving accountability across rounds.

The reviewer also needs evidence beyond the author's account, without assuming the specification is correct. Cognition sees an advantage in allowing reviewers to question insecure user instructions (Yan, 2026). A reviewer inferring intent, however, cannot confirm coverage of unseen requirements. Medication practice keeps apart two questions that software review also needs: whether a prepared dose matches the order, and whether the order suits the patient. Cognition's communication bridge lets the coding agent filter findings using broader task context. Filtering prevents irrelevant work, yet dismissing a security concern solely because the user requested that behaviour defeats the reviewer's ability to challenge the request. Dismissals need reasons that others can examine.

Tests are meant to supply that evidence by stating what the code should do. Böckeler (2026) found tests that generated expected results by rerunning the implementation; writing tests first did not reliably prevent this circularity. Her small experiment cannot settle TDD's effectiveness, but this fault can be inspected directly. The US-based Institute for Safe Medication Practices (ISMP, 2003) similarly recommends independently recalculating without seeing prior calculations. The software equivalent needs expected values grounded in requirements or worked examples. Temporal separation alone supplies no independent basis for judgement.

Shared errors can survive all these controls. Kim et al. (2025) found that LLM judges inflated assessed accuracy when they shared a model's wrong answers, motivating calibration against ground truth for each model–judge pair. This sharpens the challenge to Cognition's trust in training, although judging answers is not reviewing code. CriticGPT nevertheless caught more inserted bugs than paid reviewers, while human–critic teams hallucinated fewer problems than critics alone (McAleese et al., 2024). A second model adds catches; that does not make the pair's misses unrelated. These findings support measuring joint misses, using representative planted defects and independently checked expected outcomes. Procedural safeguards earn confidence through those results.

Acceptance criteria must nonetheless remain revisable. Schön (1996) links surprise to rethinking one's actions mid-practice, which suggests that some expectations surface only when challenged. Writing a prediction down before a check runs gives a surprising result something to contradict. When an agent edits a failing test, reviewers should record whether new evidence showed the requirement to be wrong or the assertion was simply loosened to fit the code, since both produce a green suite. ISMP Canada (2005) advises concentrating checks on high-risk processes; in software, the equivalents include authentication and irreversible deletion. A fresh context, then, improves detection but does not by itself make an independent reviewer; that depends on what the process lets the reviewer forget, keep and insist on.
