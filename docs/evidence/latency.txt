Method fix, 2026-11-11 (before Round 4): a 0ms median is not a network
measurement, so scripts/smoke-deployed.mjs's timer now starts immediately
before sending the second POST (not after awaiting its response) and stops
when the first client's SSE reveal snapshot arrives -- elapsed time from
submitting to seeing the update, as brief §7 actually asks for.

What the old runs above measured instead: the timer started only after
`await`ing the second submitter's own POST response, i.e. after that
request's round trip had already finished. The server calls sse.notify()
before sending that response (src/server.mjs), so the SSE push and the old
timer's start point left the server in the same event-loop tick and raced
back over two independent TCP connections. The near-zero and negative
values above are which of two already-in-flight responses happened to win
that race, not how long an update takes to become visible -- the "direct
inspection" of B's own request RTT mentioned above (~240ms) was the real
network time; the old method just never put that number on the clock it
reported.
