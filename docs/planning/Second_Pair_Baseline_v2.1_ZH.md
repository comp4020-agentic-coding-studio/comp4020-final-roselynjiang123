# 第二双眼睛 · 基准方案 v2.1（合并版）

2026-11-11。合并三份材料：我的 v2.0 方案、外部《教学闭环升级规格 v2》、v1.0 基准方案。本文件只写**决定和理由**；给 Sonnet 的技术合同是英文的 `docs/build-brief.md`（v2），病例内容的唯一来源是 `content/case-bank.v2.json`。v2.0 方案和外部规格都作为历史放在 `docs/planning/`，不再作为指令。

---

## 0. 一句话

两名护理学生在成人病房情境里，各自核对 6 个用药任务（先比较记录，再选下一步和依据），签名后一起看复盘；然后看训练总结、做 3 道新情境题、拿到一张可打印的结束回顾。全程 20–25 分钟。所有分数和反馈由预先写好的规则计算，运行时不用 AI。

## 1. 合并决策：两份方案冲突时选了哪个

| 议题 | 我的 v2.0 | 外部规格 | **采用** | 理由 |
|---|---|---|---|---|
| 作答结构 | 6 项 ok/problem（含过敏）＋行动＋可选自由理由 | 5 字段 match/mismatch＋行动＋结构化依据 | **外部** | 5 字段只比较“医嘱 vs 备药”，过敏和给药间隔放进“行动＋依据”。这样“记录完全一致但不能给”在数据结构上就成立，正好是核心教学点；而且沿用 v1 引擎的 5 字段，Sonnet 改动最小 |
| 依据形式 | 自由文本 ≤140 字 | 每题 3–4 个结构化选项 | **结构化，但用全局固定 7 个选项** | 自由文本无法自动评分，还要多隐藏一个字段；每题不同的选项会暗示答案，所以 7 个选项每题相同 |
| 行动选项 | continue / reprepare / hold | continue / pause / obtain missing info | **continue_checks / reprepare / pause_clarify** | 剂量或剂型准备错了，“重新备药”才是真实动作；“补充信息”没有任何一题必须用到，留着只会制造歧义 |
| 行动与字段一致性 | 有 problem 不能选 continue | 未规定 | **保留** | 是输入校验，不泄露答案；全部 match 时允许任何行动 |
| 可接受答案 | 每题一个 | 每题一组可接受的（行动，依据）配对 | **外部** | 审阅者意见可能分歧，配对集合能容纳；同时避免“暂停”成为万能答案 |
| 病例 | 6 题，第 6 题 morphine 双问题 | 6 题框架，药物未定 | **外部的 6 个学习目标＋我的药物**：C4 改为 morphine PRN 时间题 | morphine 是 S8，真实病房确实要求两人核对，让“双人”有现实依据；浓度 10 倍错误移到迁移题 T1 |
| 迁移题 | 应用外纸质前后测 | 应用内 3 题，双人、独立提交 | **两个都要** | 应用内 3 题是产品功能（Sonnet 能做，复用同一引擎）；纸质 3 题只在试玩时做前测，用来和应用内迁移题比较 |
| 总结 | 互补发现（both/onlyA/onlyB/neither） | TP/FN/FP/TN、分母、≤3 条建议、跨次回顾 | **合并**：外部的公式＋我的互补统计 | 两者不冲突；我用参考实现算出了金标准样例，Sonnet 的测试必须复现 |
| 跨次回顾 | 无 | 最近 3 次、跨次建议规则 | **只做描述性列表，不做跨次建议** | 一堂课只玩一次，跨次推断价值低、规则复杂、容易说过头；描述性表格便宜且诚实 |
| 内容治理 | version＋sources＋reviewStatus | draft/source_checked/educator_reviewed/withdrawn＋逐条 claim 来源 | **外部** | 更严格，而且可以写成自动检查（agent 不能把状态改成已审阅） |
| 声明文案 | 一行提示＋说明 | 六段英文声明 | **外部**，补一句事件日志 | 我保留了最小事件日志（打开药卡），声明必须如实写出 |
| 事件日志 | 有 | 未提 | **保留最小版本** | 课程 C10 要“人们实际做了什么”的日志；只记打开药卡，不记任何自由文本 |
| 带教指南 /guide/ | 有 | 有 | 有 | — |
| 角色 | 带教、病人、A/B 像素头像 | 只要带教和病人 | **外部** | A/B 用字母圆标就够了，少一套像素图 |
| 布局 | 记录全宽堆叠＋右侧粘性核对栏 | 两份记录并排 | **外部** | 5 字段比较的就是这两份记录，并排才方便对照；核对区放在下面两栏 |
| 时长 | 15–20 分钟 | 20–25 分钟 | 20–25 | 加了迁移题；试玩时实测 |

## 2. Sonnet 5 能不能做：范围筛选

| 功能 | 结论 | 说明 |
|---|---|---|
| 5 字段＋行动＋依据、校验、一致性规则 | ✅ 能做 | 规则全部写清，有测试 |
| 阶段流转（训练→总结→迁移→完成）、幂等推进 | ✅ 能做 | 与 v1 的 next 同一模式 |
| 计分、总结、建议、互补统计 | ✅ 能做 | 纯函数；我已生成金标准样例 `scoring-fixtures.json`，测试必须逐字复现 |
| 组合式复盘 | ✅ 能做 | 文案全部来自题库，按条件选择，不生成 |
| 题库加载、版本快照、审阅状态校验 | ✅ 能做 | 启动时校验，非法就拒绝启动 |
| 界面 | ✅ 能做，**前提是照抄** | 它看不见渲染结果。对策：参考稿 9 个状态＋两种视口的截图都放进仓库，CSS 原样复制；如果有无头浏览器就让它截图对比 |
| 像素角色 | ✅ 能做 | 已经是 16×16 字符网格数据，不需要美术判断 |
| 描述性跨次列表、打印样式、/guide/ 与 /sources/ 页面 | ✅ 能做 | — |
| 事件日志、评估导出、审阅包生成脚本 | ✅ 能做 | — |
| **医学内容的准确性** | ❌ 不能交给它 | 替代：我起草、你核实、审阅者把关；它只负责把 JSON 接进系统，不许改临床文字和审阅状态 |
| **专业审阅、真人试玩、访谈** | ❌ 不能 | 只能你做；它可以准备导出数据 |
| 自己判断“看起来像不像” | ❌ 不可靠 | 替代：参考截图＋你在第 D 轮的人工对比 |
| 跨次建议规则 | ⛔ 放弃 | 改为描述性列表（见上表） |
| 运行时 AI 带教 / 复盘 | ⛔ 放弃 | 风险和验证成本都超出本项目；网页声明明确写“不由在线 AI 生成” |
| PDF 生成服务、教师后台、账户 | ⛔ 放弃 | 用浏览器打印代替 PDF |
| 用 AI 自动审核医学内容 | ⛔ 放弃 | 低温度、RAG、提示词都不能保证医学正确 |

## 3. 最终范围

### 3.1 流程
开始页 → 建桌并邀请 → 等待（带教开场＋Before you start）→ 6 个训练病例（核对 → 已签名等待 → 复盘）→ 训练总结 → 3 个新情境（同样流程）→ 结束回顾（训练与迁移分开、此浏览器的早先练习、打印）。

### 3.2 病例（详细内容见 `docs/content/review-pack.md`）

| # | 标题（不泄题） | 药物 | 字段不一致 | 可接受的下一步＋依据 | 学习目标 |
|---|---|---|---|---|---|
| C1 | Morning tablets | paracetamol 1 g ＝ 500 mg × 2 | 无 | 继续＋总量 / 全部一致 | 单位不同不等于剂量不同 |
| C2 | Antibiotic round | amoxicillin，标签是隔壁床 SMITH | patient | 重新备药或暂停＋身份标识 | 三个标识，开放式提问 |
| C3 | After surgery | paracetamol 500 mg × 1 | dose | 重新备药＋总量 | 规格对、数量错 |
| C4 | Pain relief request | morphine 口服液 1 mg/mL，07:30 刚给过，现在 08:15，4 小时一次 | 无 | 暂停＋给药记录 | 记录一致但还没到时间；S8 两人核对的现实依据 |
| C5 | First dose of a new antibiotic | amoxicillin，penicillin 过敏，红腕带 | 无 | 暂停＋过敏记录 | 五项之外还有过敏 |
| C6 | Breathless this morning | salbutamol：医嘱吸入器 200 micrograms，备的是 5 mg 雾化 | route、dose | 重新备药＋剂型 / 总量 | 剂型变了，途径和单位都变；找到一个问题后继续查 |
| T1 | A liquid dose | morphine 10 mg/mL × 5 mL = 50 mg，医嘱 5 mg | dose | 重新备药＋总量 | 总量（从片剂迁移到液体） |
| T2 | Overnight pain relief | paracetamol PRN，昨晚 21:40 给过，现在凌晨 04:00 | 无 | **继续**＋给药记录 | 跨午夜计算；记录也可以告诉你“可以给” |
| T3 | A different antibiotic | flucloxacillin，penicillin 过敏 | 无 | 暂停＋过敏记录 | 换了药名的过敏迁移 |

训练题有 3 道“字段全部一致”（C1、C4、C5），其中两道仍要暂停；一道有两个不一致（C6）。迁移题三道的正确行动各不相同，“一律暂停”拿不到满分。

### 3.3 视觉
暖灰白背景、深蓝绿主色、琥珀色表示“需要关注”、红色只用于过敏和红腕带；正文系统字体，记录值等宽字体；两张错位记录卡图标；像素图只有带教 Lee 和每题的病人。所有颜色组合已计算对比度（≥4.5:1）。

## 4. 验证计划（validation，不是 verification）

| 问题 | 方法 | 预先写下的通过标准 | 证据文件 |
|---|---|---|---|
| 内容准确、真实吗？ | 2–3 位护士/带教/药师用审阅包打分 | 无未解决的 “inaccurate”；每题的可接受答案所有审阅者都认为能从页面信息推出 | `docs/validation/content-review.md` |
| 能自己玩完吗？ | 3–4 组试玩观察（至少 1 组护理背景、1 组非医学背景） | ≥3/4 场无需“怎么操作”的帮助；中位时长 20–30 分钟 | `sessions.md`＋导出 CSV |
| 能迁移到新情境吗？ | 试玩前纸质 3 题（与 T1–T3 同目标、不同数字）＋应用内 T1–T3 | 多数参与者在“给药记录”“过敏”两类上的行动＋依据有改善；“可以给”的题误报不增加 | `transfer.md` |
| 独立性守得住吗？互补发现会出现吗？ | 观察签名前是否交谈；导出数据里的 onlyA/onlyB | 记录每场交谈次数；每场至少出现一次“只有一人发现/选对” | `sessions.md` |
| 学生说得出“一致≠正确”吗？ | 结束访谈 5 题 | ≥3/4 护理参与者能用游戏里的例子说明 | `sessions.md` |
| 老师会用吗？ | 1 位教师看 /guide/ 并试玩 | 说得出会怎么用、要改什么 | `content-review.md` |

规则：
- `docs/validation/plan.md`（含以上标准）在**第一场试玩前**提交，commit 时间证明标准先于数据。
- 只写“在 N 场中观察到……”，不写“本游戏能提高……”。
- 先问课程负责人：同学试玩需要什么手续。口头知情同意；不收集姓名或健康信息；参与者用编号。**如果以后想发表，必须在收集数据之前申请 ANU 人类研究伦理审批。**
- 时间不够时的最小版本：2 位审阅者＋2 组试玩＋纸质前测。

纸质前测 3 题（内容同样要经你核实）：
1. 医嘱 paracetamol 1 g；备了 500 mg × 3 → 重新备药＋总量。
2. 医嘱 paracetamol 1 g，6-hourly PRN；上次 11/11 05:00，现在 11/11 09:30 → 暂停＋给药记录。
3. 过敏：penicillin；医嘱 amoxicillin（附药卡）→ 暂停＋过敏记录。
每题让参与者选行动、选依据、写一句“为什么”。

## 7. 还需要你确认的事

1. **C2 的情境是否合理**：用“药房为病人单独分装、标签写了隔壁床”来制造身份不一致，符合你见过的澳洲病房做法吗？不符合的话，可以改为备药托盘上的 “Prepared for” 标签。
2. **C6 是否也接受“暂停并澄清”**：病人有点喘，一些审阅者可能认为应先联系医生。现在只接受“重新备药”。
3. **两种 morphine 口服液浓度（1 mg/mL、10 mg/mL）**在澳洲是否都常见；S8 处理与见证的文字是否准确。
其余 ⚠ 项见审阅包。
